# 动作派 · Camera Games

浏览器本地运行的体感游戏原型。第一款游戏是切西瓜，用于验证 **MoveNet MultiPose 双人识别、手腕轨迹碰撞与 Phaser 渲染**。包含 60 秒回合与本局计分，不含登录、上传或录像。

## 运行

需要 Node.js 22（22.11 可用）或兼容 Vite 6 的 Node.js 版本，以及启用图形加速的桌面 Chrome / Edge。

```sh
npm ci
npm run dev
```

打开终端给出的 `http://127.0.0.1:5173`。模型及权重已包含在 `public/models/movenet`，运行时不请求第三方模型服务。首次加载模型并预热 GPU 可能需要几秒。

开发与预览服务器默认监听 `0.0.0.0`，同一局域网的其他电脑可通过终端显示的 Network 地址（`http://本机局域网IP:5173`）访问开发页面；需允许系统防火墙入站连接。HTTP 局域网地址可以鼠标试切，但使用摄像头需要浏览器信任的 HTTPS。只允许本机访问时使用 `npm run dev -- --host 127.0.0.1`。

- **鼠标试切**：不打开摄像头、不加载模型，用移动鼠标验证轨迹和西瓜切开效果。
- **开启摄像头**：允许浏览器权限；如系统阻止访问，还需在 Windows / macOS 的隐私设置中允许 Chrome 使用摄像头。
- 默认单人，可切换双人。双人左右站好，肩膀、髋部、双肘和手腕尽量完整入镜，不要前后重叠。
- 开始前选择摄像头、采集画质、模型输入尺寸和识别频率；游戏中可调整挥手速度门槛、骨架及摄像头背景。
- 结束体验会停止视频轨道并释放识别器。页面离开前台时暂停处理，回来后清空旧轨迹。
- 除 localhost 外，摄像头访问需要 **HTTPS**；通过局域网 HTTP 地址打开通常不能访问摄像头。

## 回合规则

- 摄像头模式要求双肩、双肘、双手腕及髋部清晰入镜（不要求膝盖或脚）。双手高于肩膀到髋部 65% 处的腹部准备线，保持约 1 秒后完成确认。双人可先后确认，确认后可以放下手；全部玩家确认且在场才倒数 3 秒。持续丢失超过 1 秒或换人会清除对应确认并取消倒数，切换到后台会重新准备；鼠标模式直接倒数。每局有效游玩 60 秒，后台暂停。
- 开局生成完整水果计划。双人共享同一计划，两侧水果类型、顺序、时间、大小及抛出高度相同，位置与横向速度镜像；只能切自己的水果。鼠标在左／右半屏模拟对应玩家。
- 西瓜 1 分、菠萝 2 分，各自半屏右上角显示分数。到时停止生成和计分，展示胜负与两种水果的命中数量。再来一局会清零并重新生成计划。
- 在第 0 / 15 / 30 / 45 / 60 秒，生成间隔分别为 1500 / 1200 / 950 / 750 / 600 ms，菠萝概率分别为 5% / 10% / 15% / 25% / 35%，区间内线性变化。最后 1.5 秒不再生成新水果。概率不保证每局实际比例，但两侧实际序列完全一致。
- 切口穿过水果中心并跟随手腕轨迹角度；果肉沿切口两侧分开。两种水果使用本机合成的不同短音效，可关闭声音。
- 结算后暂停姿态推理，保留模型和摄像头预览；再来一局时清空玩家绑定与手腕轨迹并恢复推理。点击“结束体验”释放。双方机会相同，但光线、遮挡等仍会影响识别表现。

## 技术与数据流

TypeScript + Vite + Phaser 3 + TensorFlow.js WebGL + MoveNet MultiPose Lightning。

```text
摄像头 → 按识别输入尺寸缩小到内存画布 → MoveNet 骨架和跟踪 ID
          → 左右玩家绑定 → 双手腕轨迹 → 相对运动碰撞 → Phaser 西瓜、刀光与切开特效
```

摄像头背景为镜像 `<video>`，Phaser 透明画布叠加在上方。统一使用 1280×720 逻辑坐标；映射会补偿镜像和 `contain` 留边，包括全屏。

取帧画布按识别输入长边缩放（默认 256；16:9 时约 256×144），原始摄像头预览清晰度不变。模型关键点转换回原始摄像头坐标后再用于站位和碰撞，兼容 4:3 与竖屏留边。

识别和渲染分开调度，最多一帧推理在途，不累积旧帧。检测到高速跨越西瓜时按线段碰撞，补偿西瓜在两次手腕采样之间的移动。静止、低置信度、短时丢失、异常跳点不会产生切割轨迹。水果被切后立即移除碰撞对象，避免重复切割。

页面界面暂用原生 DOM，不为这一页额外引入 React。界面与识别、游戏模块分离，后续需要复杂大厅时可再增加 UI 框架。

## 性能面板

- **识别频率**：最近一秒实际完成的模型推理次数。
- **游戏帧率**：Phaser 渲染循环统计。
- **推理 P50 / P95**：最近最多 120 次取帧与模型推理耗时，包括首次预热；不是动作到屏幕的端到端延迟。
- **实际采集**：摄像头轨道协商得到的分辨率和帧率。
- **采集帧率**：`requestVideoFrameCallback` 最近一秒的呈现回调数，是浏览器观测值，不是传感器原始帧率。

先从 720p / 30fps、模型输入 256、识别上限 30 次/秒开始。输入 320/384/512 可用于比较远处小人体的精度与延迟，60fps 采集不保证 60fps 识别。M1 MacBook Pro 可用于初步验证，但本项目没有保证任何机器的帧率。

## 验证

```sh
npm test
npm run build
# 先保持 npm run dev 运行，另一终端：
npm run test:browser
npm run test:round
npm run test:preparation
```

浏览器测试默认使用已安装的 Google Chrome（Playwright `channel: chrome`），通过模拟摄像头验证真实模型加载、推理循环、停止释放、权限错误、鼠标碰撞和响应式布局。不打开真实摄像头。截图写入 `test-results/`。可用 `BASE_URL` 指定服务地址。

`test:round` 使用鼠标和模拟时钟验证双人独立计分、倒数、60 秒结算锁分、重开清零、单人模式及窄屏结算；模拟时钟下的性能面板数值不能作为性能基准。

`test:preparation` 替换模型输出为可控模拟姿态，验证腹部线举手确认、双人先后准备、丢失取消倒数、换人重新确认、重开及响应式提示；真实摄像头下的识别准确率需要另行实测。

真实双人动作精度、光线条件、相互遮挡后的身份稳定性和实际 M1 / Windows 性能，需要现场测试。当前跟踪器使用位置关联，不具备人脸身份识别；旁观者进入站位可能在玩家丢失超时后被接入。正式产品若允许交叉换位，需要更强的身份恢复策略。
